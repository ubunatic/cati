# 111 — test suite catalog and roadmap: lighter, quieter, timed tests

**Status**: Open
**Priority**: P2 (Medium)
**Severity**: Moderate
**Category**: Testing
**Related**: loom 377, harnez 881, docs/TestTiers.md

---

/goal The cati test suite tests key behaviour without excess load or slow developer turns:
test slowness and resource hogs are cataloged, audio/benchmark/modes test times are bounded or tiered,
and a repeatable roadmap keeps runs fast and clean with measured before/after metrics; or stop and
report when blocked on a user decision.

## 1. Problem & Motivation
In parallel with loom (issue 377) and harnez (issue 881), test suites have accumulated unmeasured
slowness and resource contention during agentic workflows and developer turns (`make test` / `make test-q1`).
In `cati`, running the suite exercises double runs (fastpath 1 and fastpath 0), heavy video/image
rendering loops, real audio playback (`internal/audio`), and exhaustive flag sweeps in `cmd/`.

Baseline measurement via the new `gotester report` tool reveals that two packages dominate the entire
run: `cmd` (41.9s wall, 93.3s CPU, 493 MiB RSS) and `internal/audio` (27.1s wall, 4.5s CPU, with `TestPlayAudio` alone taking 25.46s).

## 2. Technical Specification / Findings

Baseline run (2026-10-23 via `HTO=0 gotester report ./...`):
- Total: 28 packages, 82.7s wall time, 118.1s CPU, peak RSS 493 MiB.
- `cmd` and `internal/audio` account for 69.0s out of 82.7s wall time (~83%).
- `internal/audio/TestPlayAudio` took **25.46s** because it plays real sound streams over an extended duration instead of mocking or using short fixtures.
- `cmd` runs full sweeps over all visual render modes and filters:
  - `TestModesCommandInfoAllModesAndSmartMetadataOnce`: 13.98s
  - `TestRunMediaBenchmarkVideo`: 6.37s
  - `TestModesFilterFlags`: 6.23s
  - `TestModesCommandDemo`: 5.62s
  - `TestModesCommandOptimizedFilters`: 4.27s
  - `TestModesCommandColsFlag`: 4.24s
  - `TestGoldenRenders`: 2.96s
  - `TestSSIMBenchmark`: 2.64s
- `make test` runs `go test ./...` twice (once default `CATI_FASTPATH=1`, once `CATI_FASTPATH=0` with `-tags=fastpath0`), compounding the overhead on un-cached runs.
- `testreport/` generated by `gotester` is ignored in `.gitignore`.

## 3. Roadmap (one step per milestone, measure before/after)

1. **Baseline Report (Done):** Run `gotester report` to measure wall, CPU, peak RSS per package, and top 20 slowest tests. Baseline saved in `testreport/report.md`.
2. **Audio tests bounding (Delivered in commit `424e634`):**
   - Bound `internal/audio/TestPlayAudio` to a 250ms representative audio clip and parallelized probe subtests.
   - Result: `internal/audio` wall time dropped from **27.1s down to 0.9s** (`TestPlayAudio` dropped from **25.46s to 0.39s**).
3. **`cmd` modes & benchmark test optimization:**
   - De-duplicate or streamline exhaustive flag/filter matrices in `cmd/modes_test.go` (`TestModesCommandInfoAllModesAndSmartMetadataOnce` 14s, `TestModesFilterFlags` 6.2s, `TestModesCommandDemo` 5.6s).
   - Move or guard heavy media benchmarks (`TestRunMediaBenchmarkVideo` 6.4s, `TestSSIMBenchmark` 2.6s) so unit test passes stay under target budgets.
4. **Fastpath double-run audit:** Ensure package-level caches work effectively across `CATI_FASTPATH=1` and `0` runs, avoiding duplicate work where fastpath divergence does not exist.
5. **Load and process bounds:** Spec `-p` limits where appropriate and enforce per-test timeout budgets.
